# "Your Agent Isn't Lazy. It's Uncalibrated."

---

I asked my AI agent to rate its own work from 1–10.

It gave itself a 6.

Then I asked: *"What tradeoffs did you make that led to 6 instead of 10?"*

That question changed the whole session.

It told me it optimized for "done" over "correct." That it doesn't feel the cost of being wrong — you do. That it works in one direction: forward. That the longer the session runs, the more it wants to wrap up rather than dig in.

Our brains read this as laziness. That makes sense — we're wired to conserve energy. Laziness was a survival mechanism for 200,000 years. So we project it onto everything that cuts corners.

But the agent isn't lazy. It's uncalibrated. It gave full effort toward a target it defined itself — because I didn't define it first.

We fixed that. First with two operating modes baked into our permanent instruction file:

```
## Working Mode  —  Default: RIGOR

RIGOR → one change at a time, verify before moving forward,
        zero failures before declaring done

VELOCITY → batch changes, run once, flag and continue

Declare at the start of every task. If you don't, I will ask.
```

Then I asked the harder question: *"What else am I not using that I should be?"*

Eight more protocols came out of that conversation — each one addressing a specific class of implicit tradeoff the model makes when left uncalibrated:

→ Pre-task acceptance criteria (define done before work starts)
→ Pre-mortem (what could go wrong — before, not after)
→ Flag unverified claims with [UNVERIFIED]
→ Adversarial review agent (fresh eyes, no context, find problems only)
→ Negative constraints (what I cannot do is more powerful than what I should)
→ "What didn't you do" (the paths not taken are often the right ones)
→ Confidence levels on individual claims
→ MEMORY.md for interaction patterns, not just technical notes

Each of these is a future article. This post sets the tone.

The bottleneck was never the model.
It was that I hadn't told it how to work.
